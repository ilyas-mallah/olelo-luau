# Kernels

Every kernel is a Luau function generated by `tools/gen/` from a tile description. A tile is a format, a layout, R rows
per pass, S tokens per pass and U unrolled steps, plus the order the weight vectors load in. Tiles are data in
`tools/gen/tiles.luau`, and the output sits in `src/kernels/generated/`, one module per format and read path.

## Kernels

|---|---|---|---|---|

| `f32_vector` | f32 | same, all loads first | R4 S2 U2 | prefill |
| `f32_buffer` | f32 | three `readf32` per vector, all loads first | R8 S1 U8 | decode without the fast call |
| `f32_scalar` | f32 | scalar `readf32` | R8 S1 U8 | last resort |
| `bf16_vector` | BF16 | vector read, pairwise conversion | R4 S1 U8 | decode, steps 24 columns like the activation rows |
| `bf16_vector` | BF16 | same | R4 S1 U12 | benchmark only, steps 36 columns |
| `bf16_scalar` | BF16 | scalar | R8 S1 U8 | without the fast call |
| `q8_p8` | offset binary int8, tiles of 8 rows, packed words | scalar integer ops | R8 S1 U32 | decode |
| `q8_p8` | same, one band of 4 rows | same, field extraction shared by 2 tokens | R4 S2 U32 | prefill |
| `q8_v12` | 3 offset binary bytes per f32 lane, tiles of 12 rows | `buffer.readvectorf32x3`, vector arithmetic | R12 S1 U32 | decode of a model stored in the `v12` layout |

| `q8_il4e` | int8, 4 rows interleaved by element | scalar | R8 S1 U8 | second reference, not selected |
| `q4_p4` | nibbles, tiles of 8 rows, a word per column | scalar integer ops | R8 S1 U32 | decode |

| `q4_byte` | nibbles, row major | scalar | R8 S1 U4 | second reference, not selected |

K is the stored row length, padded to a multiple of the tile's K step so no kernel has a tail. A vector kernel steps 3 x U
floats, so a row is padded with zeros.

## Q4

Q4_0 as llama.cpp computes it: per group of 32 weights a half precision scale `d`, the weight being `(nibble - 8) * d`.
The converter's nibbles and scales equal `llama-quantize` weight for weight, stored in the packed layout `p4` below. Rows
are a multiple of 8, columns a multiple of 32, padding is the nibble 8 with scale 0. The recipe stores the embedding and
the output matrix as Q8_0, which is what `llama-quantize` does for SmolLM2's tied embedding.

### Layout

- A tile is 8 rows, and a group of 32 columns of a tile is 32 words of 4 bytes, one word per column, holding the 8 rows
  of that column as nibbles. Pair `m` of rows (2m and 2m + 1) is nibble `m` for the even row and nibble `m + 4` for the odd
  row. The byte offset of weight (`row`, `k`) is `(row // 8) * 4 * kpad + (k // 32) * 128 + (k % 32) * 4 + n // 2`, with
  `n = (row % 2) * 4 + (row % 8) // 2` and the nibble `n % 2` (0 low) of that byte.
- Scales are laid out as for Q8, 8 per group in tile row order.

`tools/convert/repack_q4.py` rewrites a container with the old row major Q4 layout (a group 16 bytes, element `j` in the
low nibble of byte `j`, element `j + 16` in the high one) into this layout in place. A runtime refuses the old layout
with a message that says so.

### The packed sum

The kernel reads the packed activations of Q8 (f64 values, 128 times the group sum and the scale per group). The mask
`0x000F000F << 4m` keeps nibbles `m` and `m + 4` of a word as `16^m (a + 2^16 b)`, so one double multiply by the column's
activation adds two products. A group of 32 columns sums to `16^m (F_a + 2^16 F_b)`, starting from `-8 sx (2^16 + 1) 16^m`
(the stored group sum over 16), which cancels the offset of 8 and makes each field the signed dot product.

- Each field is at most `8 * 127 * 32 = 32 512` in magnitude, under 2^15, so `b = floor(A * 2^(-16 - 4m) + 0.5)` recovers
  the high field and `a = A * 2^(-4m) - b * 2^16` the low one. All values are integers under 2^45 times a power of two,
  so every step is exact in doubles, and the result equals the integer reference exactly.
- A 4 row band uses the masks of its two pairs, `m = 0, 1` for rows 0 to 3 and shifted 8 bits up for rows 4 to 7, which
  the epilogue undoes with powers of two.

The int8 reference reads activations with `(nibble - 8) * x` summed per group, `tests/kernels/q4.test.luau` compares the
kernels with it, with the extremes of every pair (nibbles all 15, all 0 and alternating against activations of 127 and
-127).

## Q8

Q8 is the format to use where memory matters: a quarter of the f32 bytes at about the f32 vector kernel's rate. The
weights and scales are Q8_0 as llama.cpp stores them, and the converter's result equals `llama-quantize` weight for
weight.

### Layout

- Weights are offset binary bytes, `u = w + 128`, in tiles of 8 rows. A tile column is the 8 bytes of one column, rows 0
  to 7, so a column is two u32 words. The byte offset of weight (`row`, `k`) is `(row // 8) * 8 * kpad + k * 8 + row % 8`.
- Scales are f32 holding half precision values, 8 per group of 32 columns: `((row // 8) * 8 * groups + group * 8 + row % 8) * 4`.
- Rows are a multiple of 8 and columns a multiple of 32. Padding is the byte 128 (weight 0) with scale 0.

### Activations

`ops/prepare.luau` quantizes each group of 32 activations the way llama.cpp does: `d = amax / 127` stored in half
precision, `q = round(x / d)`. A kernel reads `q` as f64 values and, per token and group, two f32: `128 * sum(q)` and
`d`. One preparation serves every product on the same input, so the cost is one pass per stage, not per matrix.

### The vector layout

`v12` stores the same Q8_0 weights for hosts with the fast vector read, where a vector instruction does three f32 lanes at
once. An f32 holds any integer below 2^24 exactly, so a lane carries three weights. With `a`, `b`, `c` the offset binary
bytes of columns `j`, `j + 11` and `j + 22` of a group of 32 (column 32 does not exist and is the byte 128), the lane is
`(a + 256 b + 65536 c) / 65536`. A group is 11 steps, a step is 4 row vectors of 3 rows, a tile is 12 rows:

- The byte offset of the lane of (`row`, `k`), with `group = k // 32`, `j = k % 32`, is `((row // 12) * groups + group) * 528 +
  (j % 11) * 48 + (row % 12) // 3 * 12 + row % 3 * 4`, and `j // 11` says which of its three weights it is.
- The scales are f32, 12 per group of 32 columns: `((row // 12) * 12 * groups + group * 12 + row % 12) * 4`.
- Rows are a multiple of 12 and columns of 32. Padding is the weight 0 in every field with scale 0.
- The data is 1.375 times the size of `p8`, 44 bytes per row and group against 32, and the container is a new file, see
  `tools/convert/repack_q8v.py`.

The activations are splat vectors (`quant.splatActivations`, `ops/prepare_vector.luau`): per token and group of 32 a
vector of `-128 sum(x)`, then for each step `256 x[j]`, `x[j + 11]` and `x[j + 22] - 256 x[j + 11]`, each in all three
lanes, and the group scale in three lanes in the second buffer. For a weight vector `v` the kernel computes

    c = floor(v), m = 256 v, f = floor(m) (= 256 c + b), a' = m - f (= a / 256),
    acc += (a' * (256 xa) + f * xb) + c * (xc - 256 xb)

which equals `a xa + b xb + c xc`. Each product is an integer below 2^24 (`f xb` is under `65535 * 127`), the sum of the
first two stays under 2^24, and adding the third cancels the `256 c xb` inside `f xb`, so every f32 step is exact. The
group's integer sum, offset included, is at most `255 * 127 * 32` in magnitude and exact. The groups are scaled and
summed in f32 in group order, so the kernel agrees with the reference within `3 x groups x 2^-24 x sum(|scale x
integer products|)`, and exactly where the scales are 1. `tests/kernels/check.luau` runs the extremes of the packed
kernel (weights and activations at 127 and -128) on this layout too.

The `v12` layout needs the fast vector read: `registry.select` refuses it without, and the message says to convert the
model with the default layout. Row slices of a worker share that do not start on a tile of 12 move the lanes of each row
into the share's own tiles when the container is read, see `container.loadSlice`.

### Why the packed sum is exact

A word holds rows 0 to 3 of one column in bytes 0 to 3. Masking with `0xFF0000FF` keeps bytes 0 and 3 as the integer
`u0 + 2^24 * u3`, and masking after a rotate by 16 keeps bytes 2 and 1 the same way. One double multiply by the
activation `x` then adds two products, and the sum over a group of 32 columns is

    A = F0 + 2^24 * F3, with F0 = sum(u0 * x), F3 = sum(u3 * x).

- Each field is below `255 * 127 * 32 = 1 036 320`, under 2^21, and `|A| < 2^21 * 2^24 + 2^21`, under 2^45. Every
  partial sum is an integer far below 2^53, so the double arithmetic is exact.
- The offset is cancelled by starting `A` at `-128 * sum(x) * (2^24 + 1)`, which is the stored group sum times
  `-(2^24 + 1)`. Each field is then the signed dot product, at most `128 * 127 * 32 = 520 192` in magnitude.
- `hi = floor(A * 2^-24 + 0.5)` recovers the high field, because the low field is under 2^23 in magnitude, and
  `lo = A - hi * 2^24` the low one. Both steps are exact.
- Each row adds `(weightScale * activationScale) * field` once per group, in group order.

The reference kernel computes the same integer sum per group and applies the scales in the same order, so the kernel and
the reference return the same values. `tests/kernels/check.luau` runs random cases and the extremes: weights all 127, all
-128 and alternating, activations all 127, all -127 and alternating.


A kernel that loads every vector of a pass first needs many live values. Past 23 spill slots native lowering skips the
function. The vector kernel therefore loads each weight vector right before its multiply (`elem`), which keeps the live
set small. The kernels that read three scalars per vector run faster with all loads first. The guard reports the
largest slot of each module.

The limit differs by target. The Windows x64 ABI keeps fewer vector registers free than System V, so the same function
spills more there: 12 rows by 2 tokens of the vector Q8 kernel needs 26 slots on `x64_ms` against 14 on `x64`, and runs
interpreted in Roblox Studio (Luau 0.748, measured 91 against 2013 MMAC/s for the 12 row, 1 token kernel in the same
module). The guard therefore lowers every module for `x64`, `x64_ms` and `a64` and fails on any skipped function, and the
prefill pass of the vector kernel is 6 rows by 2 tokens (18 slots on `x64_ms`). `tests/gen/cliff_ms.luau` holds the 12 by
2 tile that only the Windows target skips.

## Selection

`registry.select` walks a preference list per format (Q8 has `q8_p8/R8S1U32` for decode and prefill, and for a matrix stored in the `v12` layout `q8_v12`) and skips an entry that needs `vectorRead` when the probe says the
host lacks it. The probe times `f32_vector` against `f32_buffer` on a 1536 x 576 matrix for 10 ms each, and chooses the
vector kernel when it is at least 1.5 times faster. A timing that says no is repeated up to 3 times and the best ratio counts,
because CPU load can slow one timing and a model in the `v12` layout cannot run without the vector read. Without the fast call the vector read is a slow call and loses.
